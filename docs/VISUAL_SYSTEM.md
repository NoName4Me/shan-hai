# 山海之间 · 沉浸式场景视觉规则（实验版）

> 本文件记录的是跨场景可复用的视觉与实现语言，不是对任何《山海经》生物外形的统一模板。
> 首个验证场景：青丘之山／九尾狐。设计尚处于试验阶段。

## 共同世界语言

- **物质**：黑色矿石、灰白陶/骨、斑驳湿墨与极少量朱砂。色彩对比来自大的体积关系，而不是表面碎纹。
- **结构**：以主体的特征确定一种主导几何逻辑。九尾狐采用长弧、削薄的刀锋形；山体采用倾斜的矿岩大面。其他生物不可直接套用九尾狐的造型。
- **笔触**：远观是完整的轮廓，近观才出现积墨、渗化和连续的笔势。优先使用整片大笔迹，避免菱形网格、随机碎片、故意做旧的符号堆砌。
- **科技感**：以有力的分层壳体、接缝和可解释的运动关节呈现，而不是到处放屏幕、电路纹和发光格子。
- **神话感**：优先以尺度、节奏、空间和反常运动表达，不以“角色都长同一种装甲”表达。

## 青丘 / 九尾狐

**原文锚点**：《南山经》青丘之山“有兽焉，其状如狐而九尾，其音如婴儿，能食人；食者不蛊”。视觉是艺术重构，不能代替原文，不合并《海外东经》青丘国。

- 体态：狐形头、身体与四足始终可辨。躯体是完整体块，薄层装甲作为结构附着。
- 九尾：九个独立的 3D 渐细曲面，每条有独立弧度和运动相位，宽处像湿墨笔肚、末端像收锋。不是九根等间距圆管或九条同形曲线。
- 色彩：骨白和矿黑为主，朱砂只标识关键笔势；禁止全身覆盖高饱和装饰。
- 待机：小幅呼吸、转头、耳部/身体轻微律动，九尾异步游动；相机可缓慢环绕。
- 玩家触发：点击/触摸狐身保留原文入口；「唤起九尾」触发约三秒的展尾、抬身、落足与环形墨迹反馈，不必等未来 AI 系统才能体验角色回应。
- 镜头：允许拖动环视与滚轮缩放，不通过一次性固定插画来假装 3D。机位避免左侧标题遮挡狐首。

## 地形与场景

青丘不再以均匀圆锥林和青草平面作为主意象。使用大块矿石台地、倾斜山脊、湿墨沿地表流动、低浓度雾与白色天体构成深度；植被稀疏且承担轮廓引导。重复对象可考虑进一步合批实例化。

场景与角色共享的是材质、色彩和线条节奏；**山川不需要长成九尾狐的尖角，其他神兽不需要长九尾狐的机械装甲**。

## 网页实时实现与性能

- 渲染：React Three Fiber / Three.js。身体与九尾均为真实三维网格，可转动观察；墨迹贴图由 Canvas 生成，不依赖外部 CDN。
- 动态：按 useFrame 驱动。长期待机动作保留非常小的角度振幅；用户触发动作以时间包络驱动，而不是反复创建计时器或动画对象。
- 预算：像素比上限 1.5、单个主阴影贴图 1024、少量局部光源、程序化渐细尾部和共用色板；重要结构优先保留几何，远景尽量简单。后续再依据设备实际 GPU 帧时间做 LOD。
- 回退：WebGL 检测和 context-lost/renderer error 回退机制保持有效；二维场景使用同一矿黑／骨白／朱砂语言。
- 维护：资料、舆图、人物关系仍然是独立内容模块，不能因场景改版丢失原文出处、返回路径和浏览状态。

## 本次应验收的交互

1. 从舆图进入青丘，Canvas 实际加载，能够转动与缩放；
2. 能辨认狐首、四足与九条非等距大尾，场景不再只是默认低多边形草地；
3. 尾部持续异步缓动，点击「唤起九尾」可见明显但短暂的展尾、抬身与墨环；
4. 点击狐狸仍弹出文献面板，关闭后场景可继续交互；
5. 返回舆图仍停留在之前的选择状态；
6. WebGL 不可用时出现新的二维青丘，并能重试和返回。

这是首版可交互美术原型；移动端、电量/低性能设备和 GPU 负载仍需真机视觉验收，不等同于最终美术签收。
